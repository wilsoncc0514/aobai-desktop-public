# 配置、数据与隐私

更新日期：2026-10-28。以下依据当前源码，不要求用户提交真实配置或凭据。

## 数据分开保存

| 数据 | 位置/形式 | 处理边界 |
| --- | --- | --- |
| 模式、位置、层级、皮肤、Jev 开关 | 应用配置目录的 `settings.json`，当前版本5 | v1–v4 有读取迁移；保存旧版/损坏文件前备份；不手工降低版本号 |
| Codex 跟随开关、未读和已读键 | 同目录的 `codex-follow.json` | 独立于设置版本；无效/不兼容内容拒绝自动覆盖，不清空收件箱排错 |
| Jev API Key | macOS Keychain / Windows Credential Manager | 不在 JSON、日志、报告中保存或显示值 |
| Codex 日志 | `CODEX_HOME/sessions`；未设置时 macOS 用 `~/.codex/sessions`，Windows 用 `%USERPROFILE%\.codex\sessions` | 只读元数据，不能保证全部桌面/WSL/跨设备任务可见 |
| 外部皮肤 | `AOBAI_SKIN_DIR` 或默认 skin 根 | 不允许清单越界，不把损坏皮肤替换到当前画面 |

应用配置目录由 Tauri 分配：macOS 通常是 `~/Library/Application Support/com.jinhe.aobai-desktop/`；Windows 按 AppConfig 规则位于 `%APPDATA%\com.jinhe.aobai-desktop\`，测试时核对实际位置。用户目录缩写不是可提交个人绝对路径。

退出所有实例后再备份配置；备份保存在仓库之外。主设置的迁移备份形如 `settings.v3-backup.json`，无效设置备份形如 `settings.invalid-<时间戳>.json`。备份失败应记录错误，不用删除配置绕过。移走应用不等于移走设置或系统凭据；回退旧程序前先保留配置副本，不把新设置文件直接覆盖为旧版本。

## Codex 通知范围

默认关闭，用户通过托盘或右键的 Codex → 任务通知开启。最多近期32个会话、32条未读，菜单分别显示前16个任务/前12条未读；读掉后可继续查看。提醒最多保留24小时。首次每文件最多回看4 MiB，增量每轮128 KiB，约每2秒扫描；运行/等待10分钟无可识别进度显示未知，不能把未知当作完成。

明确区分主任务和子任务，异步提问仅在有 accepted=true 等明确证据时提示待处理。没有完成事件就不推断完成；本地日志缺失、无 Codex、离线或旧版深链不等于任务完成。气泡4秒后开始300ms渐隐，消失不标已读；用户点击正文/×才按对应操作处理未读。

鳌拜不显示额度、配速或重置，也不启动自动额度查询。旧 `codex_refresh` 后端命令仅兼容按需调用，没有产品菜单入口。应用不替用户登录 Codex，不读取并上传认证文件，不批准或回复任务。

## Jev 与开发环境变量

Jev 默认关闭，仅选择 idle/groom/knead/stretch/sleep。验证、测试或使用 Jev 时向 `https://api.typesafe.ai/v1/systemone` 发送模式、小时、最多五条近期动作、两项相对时间及可用动作；不发送图片、任务正文、窗口标题或文件内容。

系统凭据优先于临时开发变量 `TYPESAFE_API_KEY`；`AOBAI_BEHAVIOR_PROVIDER=jev` 可在开发环境强制启用，有效时菜单不能直接关闭，需取消变量后重启。不要在仓库、命令示例、截图或环境转储中粘贴密钥。只在用户主动选择粘贴时读取剪贴板，不要求测试者将真实密钥交给他人。

后台查询可能显示“正在读取”或“凭据读取失败”，不能据此断定密钥丢失。状态读取应不阻塞猫和菜单；安全提示由用户本人处理，测试工具不自动批准。网络失败回退本地规则，不修改帧或当前动作。
